# HyDE query builder

- Tool / model: Claude Code, Opus 5.5
- Branch: improve-seniority-matching (uncommitted, on top of existing uncommitted work)
- Objective: add HyDE (model-written job ads) to query building, as an opt-in builder.

## Changed paths
- `backend/search/hyde.py` (new): prompt, structured output, years guard, disk cache, failure memo.
- `backend/search/ranking.py`: `hyde` builder; ads replace role titles within the role vote.
- `backend/search/retrieval.py`: queries starting with `Job ad: ` skip BM25 and keep full weight on dense.
- `backend/paths.py`: `HYDE_QUERY_CACHE_DIR` (`.cache/hyde_queries`).
- `scripts/compare_query_builders.py`: replays `hyde` too.
- `tests/test_hyde.py` (new); `tests/test_matching_improvements.py` (compare test covers hyde, no live call).
- `.env.example`, `docs/application-workflow-technical-guide.md`, `docs/matching-improvements.md`.

## Decisions
- `evidence` stays the default; `hyde` only via `QUERY_BUILDER=hyde`.
- Generation reuses the profile model (`OPENAI_PROFILE_MODEL`); no new provider setting.
- Ads asking for more years than the profile states (or any years when unknown) are dropped.
- Failures are remembered per process for 5 minutes so queries and weights from two calls agree.
- Playground: `RetrievalRequest.query_builder` accepts `hyde`; EvalView Queries select offers it
  (OpenAPI and `api.d.ts` regenerated by `check.sh`). Real searches still use `QUERY_BUILDER`.
