# Adaptive collection

- Tool/model: Codex / GPT-6 session; branch unavailable (workspace is not a Git repository).
- Objective: replace fixed per-board web collection with bounded staged collection, without new user inputs.
- Changed: `backend/search/adaptive.py`, `collection.py`, `service.py`, `seek.py`, `jobspy_details.py`, `board_cooldown.py`; `tests/test_adaptive_collection.py`; `.env.example`, README and provider/cache/matching documentation.
- Behavior: web searches opt into combined defaults of 12 collector batches, 60 new description fetch attempts, 150 eligible candidates and a 120-second soft deadline. Visit board/role combinations first within budget; expand by eligible unique yield; apply early filters and history deduplication; reserve approximately 25% of small description selections for exploration. SEEK supports card-only native pages. Cache hits and inline descriptions do not consume detail slots. Final semantic shortlist, ranking and evaluation policy remain separate.
- Contracts: no API schema changes. Existing status callbacks report rounds and budget coverage. Direct Python/CLI defaults and Adzuna retain fixed collection compatibility. Cache policy includes adaptive settings and history identities; detected errors/cancellation are not cached. Existing saved data is preserved.
- Validation: standard `scripts/check.sh` passed (196 backend tests at that point, 60 frontend tests, 1 legacy test, generated contracts and production build). Two additional failure tests were then added; final full backend suite passed 198 tests. Eleven new tests cover adaptive budgets, coverage/yield, exploration, filters, duplicate paging, history continuation, time/cancellation, cache reuse, SEEK staging/rate limits and partial failures. Five mocked browser search/recovery/Find-more checks passed. Black check passed. No live board/model calls.
- Limitations: batch counts are collector operations, not raw HTTP counts. Indeed offsets can refetch earlier pages. In-flight calls can exceed the soft deadline. Budgets can leave search combinations unvisited; title/eligibility heuristics do not establish relevance. No human-labeled dataset or live latency comparison; recall/precision/speed gains remain unverified.
- Skills: applied `agents/skills/backend-engineer/SKILL.md`, `agents/skills/test-engineer/SKILL.md`; evaluation skill has the documented project-manager mismatch, so AGENTS evaluation rules supplied quality constraints.
- Remaining work: none for this scoped implementation. Future evaluation owner needs human labels and separately authorized live timing to assess quality/speed.
