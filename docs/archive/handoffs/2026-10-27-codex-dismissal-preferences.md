# Reversible dismissal preferences

- Objective: capture optional dismissal reasons and use them in future recommendations. User explicitly chose lower ranking rather than exclusion. No guarantee of zero bugs or measured matching-quality improvement was made.
- Tool/model: Codex / GPT-6 session; no Git repository/branch available. Single-agent implementation with backend, frontend, test and documentation skills; evaluation policy reviewed under AGENTS.md due to the known evaluation-skill mismatch.
- Backend: backend/schemas/contracts.py, backend/schemas/saved_profiles.py, backend/runs_api.py, backend/profiles/storage.py, backend/profiles/service.py, backend/search/preferences.py (new), backend/search/retrieval.py, backend/search/service.py.
- Frontend: frontend/src/App.vue, components/DismissJobDialog.vue and DismissalPreferences.vue (new), components/JobActions.vue, components/JobDashboard.vue, stores/jobs.ts, views/PrivacyView.vue, mocks/handlers.ts. Generated frontend/openapi.json and frontend/src/types/api.d.ts.
- Tests: tests/test_dismissal_preferences.py (new), tests/test_shared_job_index.py, frontend/tests/job-actions.spec.ts, frontend/e2e/workflow.spec.ts.
- Docs: README.md, frontend/README.md, docs/dismissal-preferences.md (new), docs/matching-improvements.md, docs/EVALUATION_MODELS.md, docs/application-workflow-technical-guide.md, docs/archive/modified_project_context.md.
- Contract: existing action PUT accepts optional dismissal input for a true dismissal; response and saved-profile schema add dismissal_feedback with empty defaults. Role/location/seniority attributes come from the workspace job. Salary requires positive finite minimum, supported currency and hourly/yearly period. Invalid input fails without mutating the action. Explicit null clears feedback; restoring removes it; legacy updates remain compatible.
- Behavior: private owner-scoped feedback is captured once per search worker; stable partition before top-K lowers exact normalized role/location matches, explicit title-level matches, or clearly comparable pay below user minimum. Automatic early-career prioritization remains primary; All jobs retains the complete retrieved pool. Scores, canonical requirements, provider prompts, public caches and model weights are unchanged. Other/no reason has no ranking effect.
- Persistence/UI: preferences follow saved profiles, survive editing/new workspaces and remain isolated between profiles. Dialog supports optional reasons, cancellation, native focus handling and salary validation. Preferences panel removes feedback without restoring the job. Offline updates retain reasons; delayed writes/GETs cannot replace newer choices. An unrelated successful action no longer hides a still-pending feedback sync warning.
- Verification: final scripts/check.sh passed with job-tracker Python: 249 backend tests, 75 frontend tests, legacy tests, OpenAPI/type generation, TypeScript and production build. Full mocked Chromium suite passed 28/28. After the final sync-warning change, both dismissal browser scenarios were rechecked, including mobile salary layout, keyboard focus/cancel, required fields and axe accessibility: 2/2 passed. Formatting and new guide source links pass.
- Failures resolved during development: feedback initially omitted from saved-profile validation model; worker initially depended on API snapshot validation; test setup had an unintended dialog click and incorrect synthetic job count; wrapped currency label included option text. Each was corrected and relevant coverage passed.
- Limits: conservative matching does not infer related roles or location equivalence. Salary parser requires explicit currency code, a nearby pay label, closed amount/range and period; missing/ambiguous/open-ended/mixed-currency pay stays unaffected. Dashboard fit sorting remains based on fit; preference ordering affects future shortlists. No live paid calls or human-labeled baseline/held-out comparisons; accuracy gains unmeasured.
