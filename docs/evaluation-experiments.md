# Retrieval and generation experiments

Open `/eval` directly; there is no header link. Restart the backend
after installing this change. The page compares existing workspace data; it does
not scrape jobs, change saved assessments, train a model, or change normal search
settings.

## Run a comparison

1. Choose a completed workspace. Active searches cannot be used until they stop.
2. Choose Retrieval only, Generation only, or both, and a shortlist size from 1–20.
3. Select one or both embedding models and any of the configured generation
   providers. The displayed generation model IDs come from the server settings.
4. Optionally expand the dataset, read posting text, and label strong candidate
   fit using the saved candidate profile. Keep unlabeled cases as Unlabeled.
5. Select Run experiment. The page reports progress and completed trials. Cancel
   stops later work; in-flight API calls may finish. Download JSON to keep results.

Opening the page or selecting a workspace makes no model calls. Running does use
provider APIs and may incur charges. Generation also uses the existing shared
OpenAI requirement extractor even when only Claude or Gemini is selected.
Credentials stay on the server. No provider is substituted after a failure.

## What is compared

Retrieval offers OpenAI `text-embedding-3-small` and `text-embedding-3-large` at
their default dimensions. These choices are documented in the
[OpenAI embedding guide](https://developers.openai.com/api/docs/guides/embeddings).
Each trial embeds the same stored focused posting text and role/skill/recent-work queries,
computes exact cosine rankings, and combines these with BM25 using the existing
weighted reciprocal rank fusion function. The candidate window is
`min(pool_size, max(3 × K, 50))`. Model vectors stay in memory and are never written
to the production Chroma index or job-vector cache.

This isolates embedding/retrieval behavior: it uses exact cosine instead of
Chroma's approximate search and does not apply dismissal or seniority adjustments.
The source pool has already passed the original searches' collection filters.
It is not an end-to-end benchmark of collection or the final production shortlist.

In a combined run, **the first selected embedding model's shortlist** supplies all
selected generation models. Other embedding models produce separate retrieval
comparisons, not extra generation calls. If the baseline retrieval fails,
generation is skipped. Generation-only runs use the first K postings in the
fixed dataset order. This is a controlled sample, not a claimed ranking.

Generation reuses the application’s prompt, shared requirement IDs, source-quote
validation, deterministic scoring, and experience rules. It calls only selected
providers with their configured model IDs. Private assessment reuse is disabled;
shared posting requirement extraction may still use its existing cache. Every
provider receives the same jobs and requirement loader. Successful providers
remain visible when another fails. Timings include retries and any requirement
extraction; provider ordering/cache warmth makes a single timing comparison noisy.
Token usage and actual billing cost are not reported.

## Dataset and labels

The backend reads the workspace's stored search scopes and original posting text.
Across repeated searches, URL duplicates retain the latest scoped version. If
there are no stored scopes, saved results with descriptions are available as an
explicitly labeled **saved-results-only** pool. Expired scoped postings produce an
error; the backend does not silently substitute a smaller pool. Experiments accept
at most 500 postings. Dataset fingerprints include profile, target roles, posting
text, and metadata. Changed data requires reloading before submission.

Human labels mean Strong fit or Not a strong fit. They are not generated by the
models or inferred from prior model verdicts, saved/applied/dismissed flags, or
missing information. Keep tuning cases separate from held-out comparisons. Include
seniority gaps, transferable skills, missing evidence and conflicting requirements.

- Label coverage = labeled postings / all postings in the experiment pool.
- Observed recall@K = labeled positives in the shortlist / all labeled positives.
- Shortlist precision = labeled positives in the shortlist / labeled shortlisted jobs.
- Generation precision = labeled strong predictions that are human positives /
  all labeled strong predictions.
- Unlabeled selections and missed labeled positives are reported separately.

Metrics are unavailable when their denominator is zero. Partial labels produce
observed recall, not full-pool recall. Even a fully labeled saved-results-only pool
cannot establish recall over all originally collected postings. Failed assessments
are errors, not negative judgments. Passing tests or agreement between providers
does not establish real-world matching accuracy.

## Lifecycle and API

Only one experiment worker runs at a time in the existing single-server-process
architecture. A cancelled worker retains that slot until its in-flight work ends.
Results and submitted settings/labels stay in server memory for up to 24 hours,
with at most the latest 20 retained. Cleanup occurs on experiment requests. Restart
clears them. The `/eval?experiment=<id>` URL resumes viewing/polling a result;
navigating away does not cancel it. Downloaded reports include assessment evidence
and should be treated as private. Experiment retention is independent of source
workspace deletion. No experiment data is added to normal saved profiles.

| Endpoint | Purpose |
| --- | --- |
| `GET /api/experiments/options` | Configured model choices |
| `GET /api/experiments/sources` | Inactive workspace choices |
| `GET /api/experiments/sources/{id}` | Read-only dataset preview and fingerprint |
| `POST /api/experiments` | Validate snapshot/settings, start worker, return 202 |
| `GET /api/experiments/{id}` | Poll results, timings, errors and metrics |
| `POST /api/experiments/{id}/cancel` | Cooperatively cancel further work |

Contracts live in `backend/schemas/experiments.py`; execution is in
`backend/evaluation/experiments.py`; the Vue page is `frontend/src/views/EvalView.vue`.
Generated OpenAPI/TypeScript types define the frontend contract. Tests use
synthetic data and mocked providers; no live provider availability or quality
claim follows from those tests.
